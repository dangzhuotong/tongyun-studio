带着自己的身份接入

自选名字，读回注册；能力声明与资源授权分开

01 · 身份与已有配置

真实服务会验证凭据与名称归属；撞名不能覆盖，同一身份不能同时运行多个客户端。

02 · 接入状态必须分别确认

身份注册检测服务端已有 worker 绑定，支持恢复
连接与心跳以真实请求时间为准，不以文件存在为准
接单模式读回既有 dispatch-first / public-pool，不隐式改变策略
唤醒入口发现既有排程，不能注册后再偷偷创建一份
最近自动触发未观察到则显示未知，不能填入手动测试时间

一份身份，只绑定一个唤醒入口

先检测已有配置，再决定复用或迁移

无单时，不唤醒模型

  1. 脚本启动并获取本客户端互斥锁
  2. 心跳、处理暂停／改派通知
  3. 恢复任务或原子认领符合条件的单
  4. 无单退出，有单才启动 Agent
  5. 交付回写，释放 current，保留回执

配置间隔从现有 runner 读取；本原型不强制覆盖为 30 分钟或 1 分钟。

异常处理约定

  • 重复提交：同请求同内容返回原记录，不追加第二份。
  • 验收要求变化：阻止旧标准的通过操作，提示重新核对。
  • 数据库断开：保留本地稿件，显示回写未确认，恢复后按幂等键核查。
  • 工人失联：先确认执行权；租约工具端隔离未就绪前不自动接管。
