# 产品需求与当前范围

目标：以项目为中心，按需使用运行、接口、数据库、版本、文件工具。所有执行状态必须有真实数据来源。

| ID | 当前能力 | 验收约束 |
| --- | --- | --- |
| R-01 | 本地项目登记、切换、移除 | 持久化、目录去重、移除不删除文件 |
| R-02 | Git 状态、暂存、提交、分支 | 保留未暂存和部分暂存内容，不自动 add 全仓；状态解析保留中文与空格路径 |
| R-03 | 项目文件和 HTTP 请求 | 读取真实内容；浏览器不能返回假请求成功 |
| R-04 | 内嵌开发工具 | 扫描目录并登记运行配置；真实进程组启停、重启和同组批量启停；生命周期区分 stopped / starting / port_open / ready / failed（一次性成功为 exited）；日志尾部来自真实输出。进程存活不等于就绪。切页不丢记录，正常退出清理。浏览器不能返回假成功 |
| R-05 | 本地目录和文件入口 | 用户明确点击才打开，写文件不得越出项目 |
| R-06 | SQLite 查询 | 只读连接，拒绝写入/DDL/ATTACH/多语句，限制执行时间和结果大小 |
| R-07 | Agent 文件快照 | 不生成虚构工人、模型、Token、心跳、任务或执行结果；校验格式、隔离项目 |

尚未接入：跨机器 worker 数据库、共享持久化记忆、真实 Agent 指令消费与回执、暂停控制、tongyun-dev 的独立 CLI / :9099、依赖自动安装和跨产品完整协议。文件快照不证明在线或执行结果可信。Dev 面板的生命周期只说明本工作台托管的进程，不表示 tongyun-dev 进程已接上。

早期 R-04 的“只拉起独立工具”设计已被内嵌面板替代。当前功能与测试证据见 [验收记录](testing/acceptance-tests.md)。

基于现有 TiDB/runner 与已创建的 task_deliveries，新增接入状态、HTML 写入和隔离预览、版本关联与独立人工验收。细节见[工作流设计](design/agent-workflow/design.md)，现状引导见[agent-start.md](agent-start.md)。设计与建表不计为前后端功能验收通过。

### 工作流设计边界（用户纠正，现行）

默认入口为项目开发现场，不是 Agent 工人总控。任务上下文嵌入当前项目，交付连接到真实文件、diff、PR、测试与运行预览。Agent 使用自身客户端定时能力；工作台不负责统一安装或守护各客户端的排程。原生自动化不承诺无单零模型消耗。
